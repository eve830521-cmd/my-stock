# 기업 폴더 생성 및 보고서 작성 가이드 (Corporate Folder Creation & Workflow Guide)

사용자가 새로운 기업 분석 폴더를 생성해달라고 요청할 경우, 단순한 폴더 생성을 넘어 **고품질의 Phase 1/2/3 보고서를 순차적으로 작성하기 위한 완벽한 작업 환경(컨텍스트 유지)**을 구축하는 것을 목표로 합니다. 

과거 '하이록코리아', '코미코' 분석 시 단계가 넘어갈수록 맥락(Context)이 유실되어 보고서 퀄리티가 낮아지는 문제가 있었습니다. 이를 방지하기 위해 다음 규칙을 엄격히 따릅니다.

## 1. 디렉토리 및 템플릿 생성 규칙
새 기업 폴더는 항상 `stock_research` 디렉토리 내에 생성하며, 내부에는 다음 3개의 하위 폴더와 템플릿 파일을 생성합니다.

* **1_Raw_Data/** 
  * `[기업명]_분석기초.md` (빈 파일)
  * `산업동향.md` (빈 파일)
  * *참고: 이 폴더의 내용은 사용자가 직접 리서치하여 채워 넣습니다.*

* **2_Context_Cache/** (단계별 정보 유실 방지용)
  * `Phase1_Report.md`: Phase 1 보고서 작성 시 참고한 핵심 컨텍스트 요약용
  * `Phase2_Story.md`: Phase 2 내러티브 작성 시 도출된 주요 스토리라인 요약용
  * `Phase3_Summary_Cache.md`: Phase 3 밸류에이션(DCF 등)을 위해 필요한 수치 및 핵심 가정 요약용

* **3_Final_Reports/** (최종 출력물)
  * `Phase1_Report.md`: 1단계 최종 보고서 템플릿
  * `Phase2_Story.md`: 2단계 최종 보고서 템플릿
  * `Phase3_DCF.md`: 3단계 최종 보고서 템플릿
  * `[기업명]_Master_Report.md`: 1~3단계를 종합한 마스터 보고서 템플릿
  * `generate_html.py`: 마크다운을 HTML로 변환하는 스크립트 복사

## 2. 템플릿 내부 지침 (Quality Control)
생성되는 `2_Context_Cache` 및 `3_Final_Reports`의 마크다운 템플릿 파일 최상단에는, 에이전트가 문서를 작성할 때 **반드시 읽어야 하는 선행 파일(Raw Data 및 이전 Phase 결과물) 목록과 컨텍스트 유지 지침**을 명시하여(예: 주석 처리) 품질 저하를 예방합니다.

## 3. 보고서 작성 워크플로우
1. 사용자가 `1_Raw_Data` 폴더에 기초 데이터를 모두 정리합니다.
2. 사용자가 "Phase 1 작성해줘"라고 요청하면, 에이전트는 **반드시 `1_Raw_Data` 내의 모든 파일을 꼼꼼히 정독**한 뒤 Phase 1을 작성합니다.
3. 단계가 진행될 때마다(Phase 2, 3), 에이전트는 이전 Phase의 Final Report와 `2_Context_Cache`의 내용을 다시 한번 읽고 **일관된 맥락과 논리**를 유지해야 합니다.

## 4. 자료 갱신 시 리셋 및 상호 검토 워크플로우 (Zero-Base & Red Teaming)
1. **완전 초기화 (Zero-Base 리서치)**: 사용자가 기존 1_Raw_Data 파일을 삭제하고 새로운 사업보고서나 동향보고서를 업로드한 뒤 분석을 요청할 경우, **과거에 작성된 기존 보고서들의 내용을 철저히 배제**하고 현재 폴더에 있는 최신 Raw Data만을 기반으로 처음부터 새롭게 분석을 시작합니다.
2. **웹 검색을 통한 능동적 리서치**: 분석 초기화 시, 제공된 Raw Data에만 의존하지 않고 적극적인 웹 검색을 수행하여 산업의 최신 동향과 매크로 환경을 파악해 산업동향.md 등을 자체적으로 채워 넣고 분석을 보완합니다.
3. **단계별 상호 검토 (Step-by-step Review)**: Phase 1, Phase 2, Phase 3 등 각 보고서를 작성한 후에는 절대 임의로 다음 단계로 넘어가지 않습니다. 반드시 사용자가 결과물을 검토하고 피드백(질문/의견)을 제시할 때까지 대기합니다.
4. **객관적/중립적 피드백 수용 (Red Teaming)**: 사용자의 의견이나 질문에 대해 **무조건적으로 호의적이거나 동조하는 태도(Sycophancy)를 지양**합니다. 순수하게 논리적이고 팩트 중심적인 관점에서 사용자의 주장을 중립적으로 검토합니다. 합당한 경우 보고서에 적극 반영하여 재작성하되, 논리적 오류나 맹점이 있다면 객관적으로 지적하며 토론합니다.
